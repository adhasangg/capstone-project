4. Sequence Diagram: Protokol Keamanan Double-Blind & E2EE (Standar OMG UML 2.5)

Mekanisme privasi kriptografis dari otentikasi tanpa jejak hingga pertukaran pesan terenkripsi berbasis Web Crypto API (Aktor Stickman pada Lifeline).

sequenceDiagram
    autonumber
    actor M as Mahasiswa (Browser)
    participant S as Server ElysiaJS (API)
    participant DB as PostgreSQL (Drizzle)
    actor K as Konselor (Browser)

    Note over M,S: FASE 1: ONE-WAY PSEUDONYMOUS AUTHENTICATION
    M->>S: POST /api/auth/google (Google ID Token)
    Note over S: 1. Verifikasi Google TokenInfo
2. Hashing: HMAC-SHA-256(Google_Sub, PEPPER)
3. Buang email & nama asli dari memori
    S->>DB: Query / Insert ke `users_auth` (hashed_identity, role='student')
    DB-->>S: Return UUID & Role
    S-->>M: JWT Sesi (userId, role='student', pseudonym)

    Note over M,K: FASE 2: EPHEMERAL SESSION PSEUDONYM TICKETING
    M->>S: POST /api/sessions/create (Lampiran: dass21_score, vak_result)
    Note over S: Terbitkan Pseudonim Sesi Baru: "Sahabat Pelita-27"
    S->>DB: INSERT `counseling_sessions` (student_pseudonym, dass21_score, vak_result, status='waiting')
    K->>S: GET /api/sessions/queue (Auth: Counselor JWT)
    S->>DB: SELECT counseling_sessions WHERE status='waiting'
    DB-->>S: Data Tiket ('Sahabat Pelita-27', dass21_score, vak_result)
    S-->>K: Antrean Triage (Identitas asli mahasiswa tidak ditampilkan)

    Note over M,K: FASE 3: CLIENT-SIDE ENCRYPTED CHAT (AES-GCM-256 & PBKDF2)
    K->>S: POST /api/sessions/:id/accept (Klaim Tiket -> status='active')
    M->>M: Turunkan Kunci Sesi (PBKDF2 SHA-256 100k iterasi)
& Enkripsi Pesan via Web Crypto API (AES-GCM-256 + IV 12-byte Hex)
    M->>S: POST /api/chat/:id/send (encryptedContent = Ciphertext Base64, iv = Hex)
    S->>DB: INSERT `messages` (session_id, sender_type='student', encrypted_content, iv)
    Note over S,DB: Penyimpanan Ciphertext: Tabel `messages` tanpa kolom sender_id
    K->>S: GET /api/chat/:id/messages (Ambil Riwayat Ciphertext & IV)
    S-->>K: Return Daftar Pesan (`encrypted_content`, `iv`, `sender_type`)
    K->>K: Dekripsi Pesan di Browser Konselor (decryptClientMessage)

5. Class Diagram & Relasi Entitas Basis Data (Standar OMG UML 2.5 - 4 Tabel Aktual)

Struktur kelas entitas domain 3 kompartemen dan pemodelan relasi 4 tabel basis data PostgreSQL Drizzle ORM (`users_auth`, `counselors_profile`, `counseling_sessions`, `messages`).

        +updateUserRole()
    }

    class counselors_profile {
        +UUID id PK
        +UUID user_id FK_UK
        +VARCHAR_100 pseudonym_name
        +TEXT public_key
        +BOOLEAN is_available
        +TIMESTAMPTZ created_at
        +TIMESTAMPTZ updated_at
    }

    class counseling_sessions {
        +UUID id PK
        +UUID student_id FK
        +UUID counselor_id FK_Nullable
        +VARCHAR_100 student_pseudonym
        +JSONB dass21_score
        +JSONB vak_result
        +ENUM status
        +TIMESTAMPTZ created_at
        +TIMESTAMPTZ closed_at
        +createTicket()
        +acceptTicket()
        +closeTicket()

    class messages {
        +UUID id PK
        +UUID session_id FK
        +ENUM sender_type
        +TEXT encrypted_content
        +VARCHAR_64 iv
        +TIMESTAMPTZ timestamp
        +sendMessage()
        +getMessages()
    }

    CHECK_AUTH -- "Sudah Login" --> SYNC_API

Alur metodologis pelaksanaan UAT berbasis Google Form dan evaluasi kemudahan sistem menggunakan instrumen baku System Usability Scale (SUS) 10 butir (Brooke, 1996; Bangor et al., 2008).
