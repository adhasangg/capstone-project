3. Sequence Diagram: Protokol Keamanan Double-Blind & E2EE

Mekanisme privasi matematis (Boneh & Shoup) dari otentikasi tanpa jejak hingga enkripsi percakapan berbasis Web Crypto API.

sequenceDiagram
    autonumber
    actor M as Mahasiswa (Browser)
    participant S as Server ElysiaJS (API)
    participant DB as PostgreSQL (Drizzle)
    actor K as Konselor (Browser)

    Note over M,S: FASE 1: ONE-WAY ANONYMOUS AUTHENTICATION
    M->>S: POST /api/auth/google (Google ID Token)
    Note over S: 1. Verifikasi Google Signature
2. Hashing: SHA-256(Google_Sub + PEPPER)
3. Buang email & nama dari memori
    S->>DB: Query / Insert ke `users_auth` (hashed_identity, role='student')
    DB-->>S: Return UUIDv7 & User Status
    S-->>M: JWT Anonim (userId, role='student', pseudonym='Mahasiswa #4021')

    Note over M,K: FASE 2: ATTACHED TRIAGE & DOUBLE-BLIND TICKETING
    M->>S: POST /api/sessions/create (Lampiran: dass21_score, vak_result)
    S->>DB: INSERT `counseling_sessions` (vak_result JSONB, dass21_score JSONB)
    Note over S,DB: Scoping: Konselor TIDAK BISA JOIN ke users_auth
    K->>S: GET /api/counselor/queue (Auth: Counselor JWT)
    S->>DB: SELECT sessions WHERE status='waiting'
    DB-->>S: Data Tiket ('Mahasiswa #4021', dass21_score, vak_result)
    S-->>K: Antrean Tiket + Lampiran Triage (Identitas Asli Aman)

    Note over M,K: FASE 3: END-TO-END ENCRYPTED (E2EE) CHAT
    K->>M: Pertukaran Public Key Kriptografi (RSA-OAEP)
    M->>M: Generate Pesan + Enkripsi Ciphertext via Web Crypto API (AES-GCM)
    M->>S: WS Send Message (encrypted_content = Base64 Ciphertext, iv)
    S->>DB: INSERT `messages` (encrypted_content, iv, sender='student')
    Note over S,DB: Zero-Knowledge: Peladen & Admin DB hanya melihat Ciphertext acak
    S->>K: Forward WS Message (Ciphertext)
    K->>K: Dekripsi Pesan di Browser Konselor menggunakan Private Key
